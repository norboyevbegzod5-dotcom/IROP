# IROP — Telegram-агент РОПа

Бот-руководитель отдела продаж для троих продажников (Саидмурод, Аслбек,
Муроджон): проводит утренний стендап и вечерний отчёт по вопросам, принимает
разовые задачи от руководителя текстом через AI и следит за дедлайнами.

**Продакшн:** [render.com](https://render.com), сервис `IROP`,
деплой из ветки `master` этого репозитория (`render.yaml` — blueprint).
Публичный адрес мини-аппа = `RENDER_EXTERNAL_URL`, подхватывается автоматически.

## Как это устроено

- `bot/checkins.py` — цели утреннего стендапа и вечернего отчёта (вопросы по ним
  задаёт AI, по одному за раз) и расписание, когда их проводить.
- `bot/templates.py` — фиксированные периодические задачи с одним подтверждением
  (сейчас — недельный отчёт по пятницам).
- `bot/db.py` — SQLite-база (`data/irop.db`): сотрудники, шаблоны, задачи,
  сессии чек-инов.
- `bot/scheduler.py` — фоновые job'ы: запуск стендапа/вечернего отчёта, рассылка
  напоминаний по шаблонам, отметка просрочки, вечерняя сводка руководителю (20:00).
- `bot/handlers.py` — команды, кнопки и разбор текстовых ответов сотрудников.
- `bot/ai.py` — разбор свободного текста руководителя в структурированную задачу
  через OpenAI (function calling).
- `bot/webapp.py` + `bot/webapp_static/index.html` — Telegram Mini App: чат-интерфейс,
  в котором и проходит стендап/итоги дня (см. ниже).
- `bot/telegram_auth.py` — проверка подписи Telegram WebApp initData.

## Деплой на Render (продакшн)

1. Форкните/склонируйте репозиторий, запушьте в свой GitHub.
2. На render.com: **New → Blueprint** → выберите репозиторий — Render прочитает
   `render.yaml` и создаст веб-сервис на плане **Starter** (нужен для работы
   24/7 без «засыпания» и для постоянного диска).
3. Заполните секреты, которые попросит форма (`sync: false` в `render.yaml`):
   `BOT_TOKEN`, `ADMIN_CHAT_ID`, `OPENAI_API_KEY`.
4. После первого деплоя зайдите в сервис → вкладка **Disk** → **Add Disk**:
   имя `irop-data`, mount path `/var/data`, размер 1 GB (~$0.25/мес) — без
   этого SQLite будет стираться при каждом передеплое.
5. `WEBAPP_URL` заполнять не нужно — Render сам даёт `RENDER_EXTERNAL_URL`, бот
   подхватывает его автоматически.

## Локальный запуск (разработка)

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. Узнайте свой `chat_id` (например, напишите боту [@userinfobot](https://t.me/userinfobot)).
3. Скопируйте `.env.example` в `.env` и заполните:

```bash
cp .env.example .env
```

```
BOT_TOKEN=токен_от_BotFather
ADMIN_CHAT_ID=ваш_chat_id
TIMEZONE=Asia/Tashkent
BOT_NAME=Шеф
OPENAI_API_KEY=ключ_от_platform.openai.com
OPENAI_MODEL=gpt-4o-mini
WEBAPP_URL=https://ваш-туннель.loca.lt
WEBAPP_PORT=8080
```

`OPENAI_API_KEY` нужен только для постановки задач текстом (см. ниже). `WEBAPP_URL`
нужен для мини-аппа (см. раздел ниже) — без него бот работает в текстовом режиме
в обычном чате.

4. Установите зависимости (виртуальное окружение `.venv` уже создано и готово):

```bash
.venv/Scripts/python.exe -m pip install -r requirements.txt
```

5. Запустите бота:

```bash
.venv/Scripts/python.exe main.py
```

**Как бот получает сообщения.** На Render — через **вебхук**: Telegram сам
присылает каждое обновление на `https://<сервис>.onrender.com/telegram/<секрет>`, и
оно попадает ровно в один экземпляр бота — даже в минуту деплоя, когда работают
старая и новая версии (раньше в это время приходили двойные ответы). Секрет в адресе
и в заголовке `X-Telegram-Bot-Api-Secret-Token` выводится из `BOT_TOKEN`, настраивать
ничего не нужно. Локально — опрос (`getUpdates`). Режим можно задать явно:
`TELEGRAM_MODE=webhook` или `polling`.

⚠️ Не запускайте локальную копию с боевым `BOT_TOKEN`: в режиме опроса она снимает
вебхук, и сообщения пойдут к ней, а не на Render. Боевой бот проверяет вебхук раз в
10 минут и возвращает его себе, после чего локальная копия начнёт падать с `Conflict`.
Для разработки используйте отдельного тестового бота.

## Первый запуск

- Каждый из троих сотрудников пишет боту `/start` и выбирает своё имя кнопкой —
  так его Telegram-аккаунт привязывается к записи в базе.
- Кнопка **«Открыть»** у поля ввода (menu button) открывает мини-апп: сотрудникам —
  их чат с РОПом, задачи и сделки, руководителю (chat_id из `.env`) — админку. Бот
  настраивает её сам при каждом запуске (нужен https-адрес `WEBAPP_URL`) и убирает
  меню команд «/».
- Всё управление у руководителя — в админке, команды для этого не нужны. Старые
  команды (`/status`, `/team`, `/style`, `/learn`, `/knowledge`, `/forget`, `/copies`)
  по-прежнему работают, если их набрать вручную.

## AI-чат руководителя

Руководитель просто пишет боту (текстом или голосом), и AI сам понимает, что это:

- **вопрос о команде** — «сколько встреч сегодня сделали ребята?», «кто не сдал итоги
  дня?», «как Аслбек по плану?». AI отвечает по данным бота: планы, цифры из вечерних
  отчётов за месяц, тексты отчётов за 3 дня, статус чек-инов, открытые задачи и
  сегодняшние сообщения сотрудников (`bot/admin_context.py`). Если данных нет — так
  и говорит, цифры не выдумывает;
- **поручение** — «Аслбеку 150 звонков за неделю» — ставит задачу (см. ниже).

Отчёты стендапа и итогов дня, задачи и важные уведомления приходят в этот же чат.
Тот же AI-чат есть в админке, на вкладке «💬 AI-чат»: переписка общая, поручение
там можно сразу отменить кнопкой. Копии обычных диалогов сотрудников с AI по
умолчанию выключены (включаются в админке, «⚙️ Настройки»,
например чтобы исправлять ответы AI и обучать его). Вопросы, которые AI передал
руководителю (скидки, деньги, конфликты), приходят всегда с пометкой «❗ Нужно твоё
решение».

## Админка руководителя

Отдельная веб-страница по адресу `/admin/<секрет>` — открывается кнопкой «Открыть» в
чате руководителя с ботом (адрес можно открыть и в браузере на компьютере). Три
вкладки: «📊 Статистика» (всё ниже), «💬 AI-чат» и «⚙️ Настройки» (характер AI-РОПа,
копии диалогов, база знаний). Логина нет, но адрес с
секретом не угадать; по умолчанию секрет выводится из `BOT_TOKEN`, сменить ссылку —
задать `ADMIN_PANEL_TOKEN`.

- **Планы сотрудников**: звонков в день, план продаж в месяц (сум), новых подключений
  в месяц — для каждого сотрудника.
- **Команда**: звонки, продажи (фактические поступления денег), подключения и договоры —
  факт против плана за сегодня / неделю / месяц.
- **Статистика по сотрудникам**: план/факт с прогрессом, встречи, КП, договоры, сколько
  отчётов сдано из рабочих дней и сколько с опозданием.
- **Сегодня**: кто уже сдал стендап и итоги дня (красным — только после дедлайна).
- **Цели**: задачи с числом — прогресс, прогноз, статус (успевает / на грани / не успевает).
- **Рейтинг**: сотрудники по выбранной метрике за период (звонки, встречи, КП,
  договоры, поступления, подключения) с серией отчётов.
- **Воронка команды**: звонки → проведённые встречи → КП → договоры с конверсией
  каждого шага, рядом — назначенные встречи и поступления.
- **Сделки**: сколько сделок на каждом этапе и список — зависшие сверху.
- **Отчёты сотрудников**: тексты стендапов и итогов дня за период.
- В карточке сотрудника — 🔥 сколько рабочих дней подряд он сдаёт итоги дня или
  «пропуск итогов: N раб. дн.».

Цифры берутся из вечерних отчётов: AI при завершении итогов дня извлекает звонки,
встречи, КП, договоры, поступления и новые подключения (`daily_metrics`). Планы тоже
уходят в AI — в итогах дня он сравнивает факт с планом («План был 40 звонков. Сколько
фактически?»). План на день/неделю для продаж и подключений — месячный план,
пропорционально рабочим дням.

## Обучение AI: база знаний и образцы ответов руководителя

Руководитель учит AI без кода и деплоя:

- **База знаний.** Админка → «⚙️ Настройки» → «База знаний AI»: цены, условия,
  продукты, скрипт, как отвечать на возражение; там же список и удаление. (Команды
  `/learn`, `/knowledge`, `/forget` тоже работают.)
- **Образцы ответов.** Руководителю приходят копии диалогов «💬 вопрос сотрудника →
  🤖 ответ AI». Если ответить на такую копию своим вариантом, он сохранится как образец,
  а бот предложит сразу отправить исправленный ответ сотруднику.

Перед каждым ответом сотруднику (в свободном чате и в чек-инах) бот подбирает записи,
относящиеся к вопросу, и подставляет их в промпт: факты — как то, на что AI обязан
опираться, образцы — как манеру и позицию руководителя. Пока база небольшая, AI видит
все факты; когда она вырастет, — самые близкие к вопросу (`bot/knowledge.py`).

## Характер AI-РОПа: строгий или мотиватор

Руководитель выбирает в админке, «⚙️ Настройки» (для каждого сотрудника или сразу
всем). Характер влияет на свободный AI-чат, тон вопросов в стендапе и итогах
дня и на фидбэк, который сотрудник получает в конце чек-ина:

- **🔥 Строгий** — жёстко, коротко, без комплиментов; требует конкретики и цифр,
  прямо называет слабые результаты и ставит требование на следующий шаг. Критикует
  только работу, без оскорблений и унижения.
- **🚀 Мотиватор** (по умолчанию) — опирается на хорошие цифры и успехи, хвалит за
  конкретные факты, показывает, как вырасти ещё; при слабых цифрах — один понятный
  шаг на завтра вместо ругани.

Тексты характеров — в `bot/styles.py`.
- Сотруднику доступна команда `/tasks` — список задач на сегодня.

## Мини-апп (Telegram Web App)

В мини-аппе два раздела (вкладки сверху):

1. **💬 РОП** — чат: стендап, итоги дня и свободный AI-чат (текстом или голосом).
2. **📋 Задачи** — задачи от руководителя. На вкладке — счётчик активных задач
   (красный, если есть непринятые). Внутри: сводка «активных / ждут принятия /
   просрочено», карточки задач с живым отсчётом до дедлайна («осталось 2 ч 14 мин»
   / «просрочено на 3 ч»), кнопка «🖐 Принять» и завершённые задачи за 14 дней.
   В уведомлении о новой задаче есть кнопка «📋 Все мои задачи», которая открывает
   мини-апп сразу на этом разделе (`?tab=tasks`).

Стендап и итоги дня проходят внутри Telegram Mini App — отдельного окна с
чат-интерфейсом, которое открывается по кнопке прямо в Telegram, а не как
разрозненные сообщения в обычном чате. На Render всё уже настроено — этот
раздел актуален только для локальной разработки.

**Как поднять локально для теста** (нужен публичный HTTPS-адрес, `localhost`
Telegram не откроет):

```bash
npx --yes localtunnel --port 8080 --subdomain ваш-уникальный-саб домен
```

Скопируйте выданный `https://....loca.lt` адрес в `WEBAPP_URL` в `.env` и
перезапустите бота. Фиксированный `--subdomain` важен: если туннель
переподключится, адрес останется тем же и не придётся снова лезть в `.env` и
перезапускать бота.

⚠️ При каждом перезапуске самого бота (не туннеля) соединение туннеля с
локальным портом рвётся и его нужно перезапускать заново — это особенность
localtunnel, а не мини-аппа. Для постоянной работы (не только для теста) нужен
нормальный хостинг с собственным доменом вместо туннеля.

Кнопка «💬 Открыть чат» появляется у сотрудника после регистрации (`/start`), а
по утрам/вечерам бот сам присылает кнопку «🚀 Начать рабочий день» /
«🌙 Подвести итоги дня». Открыв мини-апп, сотрудник видит всю переписку за
сегодня и либо жмёт кнопку начала (если чек-ин ещё не начат), либо просто
печатает ответ в поле внизу.

## Утренний стендап и вечерний отчёт

Внутри мини-аппа (или в обычном чате, если `WEBAPP_URL` не настроен) чек-ин ведёт
AI. Фиксированных вопросов нет: у AI есть только цель разговора, а вопросы он
задаёт сам, по одному, исходя из предыдущих ответов — уточняет расплывчатое и не
переспрашивает то, что уже сказано. Как только всё выяснено, AI завершает
разговор (не больше 10 ответов сотрудника).

**Стендап, 09:00** (дедлайн — 30 минут): с какими клиентами вчера говорил, что
они ответили, какие следующие шаги, с кем будет говорить сегодня.

**Итоги дня, 18:30** (дедлайн — 90 минут): звонки (сколько и кому), встречи, КП,
договоры, поступившие деньги — в цифрах, со сверкой с утренним планом.

В контексте у AI — предыдущий отчёт сотрудника и его задачи на сегодня. Сжатый
отчёт с цифрами AI составляет сам и сразу отправляет руководителю. Если сотрудник
не завершил чек-ин к дедлайну — ему приходит напоминание, а руководителю —
уведомление о просрочке. Цели чек-инов редактируются в `GOALS` в
`bot/checkins.py`.

**Итоги дня формой.** В мини-аппе вместо переписки можно нажать «📝 Итоги дня
формой» (или «Заполнить цифры формой», если итоги уже начались в чате): счётчики
для звонков, встреч, КП, договоров и новых клиентов, поля для сумм в сумах и
необязательный комментарий «с кем говорил». Цифры сохраняются ровно как введены —
без разбора AI; AI только пишет фидбэк и отчёт руководителю. Из комментария, как из
обычного сообщения, ставятся задачи и обновляются сделки. Поля формы —
`FORM_FIELDS` в `bot/checkins.py`.

## Автозадачи по чату сотрудника

Если из сообщения сотрудника следует действие с конкретным сроком, AI сам ставит
задачу. Пример: «Evos сказал перезвонить через 2 дня в 18:00» → задача «🤖 Перезвонить
Evos» на послезавтра, 18:00.

- Относительные сроки («завтра», «через 2 дня», «в пятницу») AI считает от текущего
  времени в `TIMEZONE`. Без срока («надо бы позвонить») задача не ставится, дубли
  открытых задач — тоже.
- Сотрудник получает «📅 Поставил задачу …», напоминание приходит за 15 минут до
  времени (если время не названо — в 10:00 того дня, срок до 19:00).
- Руководитель получает уведомление с цитатой и кнопкой «🚫 Отменить».
- В мини-аппе задача видна в разделе «Задачи» с пометкой 🤖 и отсчётом; принимать её
  не нужно. Просроченной она считается через 2 часа после срока — сотрудник обычно
  отчитывается уже после звонка. Когда он напишет «перезвонил Evos, …», AI закроет
  её сам (см. ниже).

Настройки — `AUTO_TASK_*` в `bot/config.py`.

## Автозакрытие задач по тексту сотрудника

После каждого сообщения сотрудника (текст или голосовое, в чате или мини-аппе, в
чек-ине или свободном чате) AI сверяет его с открытыми задачами: всеми задачами от
руководителя и сегодняшними задачами по шаблонам. Если сотрудник прямо сообщает,
что задача выполнена целиком («отправил КП в Makro»), AI её закрывает:

- сотрудник получает «✅ Закрыл задачу …»;
- руководитель — уведомление с цитатой-основанием и кнопкой «↩️ Вернуть в работу»
  на случай ошибки AI (задача вернётся в прежний статус);
- в разделе «Задачи» мини-аппа задача переходит в «Завершённые» с пометкой
  «закрыл AI» и цитатой.

Планы («сегодня отправлю», «gaplashaman»), частичный прогресс («40 звонков из 150»),
ответы цифрами на вопросы опроса («5») и сомнительные случаи задачу не закрывают.
Цитата-основание проверяется кодом: она должна дословно быть в сообщении и содержать
слова, а не только числа.

## Интеграция с GFSupport (CRM отдела)

Бот берёт объективные факты по менеджерам из GFSupport — звонки с АТС (с разговором
и недозвоном), встречи, КП, выигранные сделки, оплаты, воронку, просроченные задачи,
причины проигрышей и с кем человек говорил. Только чтение, один адрес
`GET /api/support/public/agent-facts` (подробности — `docs/GFSUPPORT_INTEGRATION.md`,
код — `bot/crm.py`, ответы кэшируются на 5 минут).

**GFSupport — единственный источник цифр.** Каждые 5 минут (и перед сводкой, целями и
админкой) `bot/crm_sync.py` копирует факты по дням за 62 дня в таблицу `crm_metrics`.
Статистика, рейтинг, воронка, планы, цели, сводка 20:00 и AI берут звонки, встречи, КП,
договоры и деньги только оттуда; со слов сотрудника — только **новые подключения**
(CRM их не считает). Цифры, которые сотрудники вводили сами раньше, остаются в
`daily_metrics` нетронутыми, но нигде не показываются. Своя мини-CRM бота (`deals`) при
подключённой CRM не обновляется и не показывается — вместо неё сделки GFSupport.

- **Админка → «📡 Действия по CRM»**: за выбранный период по каждому сотруднику —
  звонки (разговор/недозвон) и по дням (видно пустые дни), встречи, КП, договоры,
  деньги, кому звонил, зависшие сделки и без следующего шага, причины проигрышей,
  воронка, просроченные задачи.
- **Итоги дня**: в форме — только «новых клиентов» и комментарий, цифры дня из
  GFSupport показаны над ней. В диалоге AI цифры не спрашивает — спрашивает про
  клиентов, договорённости и новые подключения.
- **Стендап**: AI спрашивает про конкретные зависшие сделки и сделки без следующего
  шага и про тех, с кем человек говорил вчера.
- **Мини-апп → «🤝 Сделки»**: открытые сделки сотрудника в GFSupport (только просмотр).
- **Сводка 20:00 и AI-чат руководителя**: цифры GFSupport, отметка, кто не сдал итоги,
  зависшие сделки из CRM.

Цифра звонков CRM — «не меньше, чем»: звонок считается по ответственному за обращение.
Без `CRM_FACTS_KEY` или до первой удачной синхронизации бот работает на самоотчёте,
как раньше; если CRM временно не отвечает — на последних скопированных фактах.

**Настройка:** на Render добавить переменную `CRM_FACTS_KEY` (значение — из файла
ключа от GFSupport). Ключ не коммитить и не публиковать; перевыпускается в GFSupport.

## Сделки (мини-CRM)

Из того же разбора сообщения AI вытаскивает клиентов/бренды и этап: разговор →
встреча → КП → договор → оплата (или отказ). Доска собирается сама из стендапа,
итогов дня и обычного чата; сделка двигается только вперёд.

- В мини-аппе — вкладка «🤝 Сделки»: сделки по этапам, кнопки «→ следующий этап» и
  «✖️ Отказ»; зависшие (5+ дней без движения) подсвечены, их число — на вкладке.
- Сотрудник получает «📇 Сделки: Evos → Встреча», руководитель — «💰 оплата по
  сделке …», когда сделка дошла до оплаты.
- Зависшие сделки — в сводке 20:00, в админке и в AI-чате руководителя.

Логика — `bot/deals.py`, таблица — `deals`.

## Голосовые сообщения

Сотрудник может отвечать голосом — и в чек-ине, и в свободном чате:

- **в обычном чате с ботом** — записать обычное голосовое Telegram;
- **в мини-аппе** — как в Telegram: удерживай 🎤 — идёт запись, отпустил — отправлено,
  свайп влево — запись отменена (ничего не отправится).

Бот распознаёт голос через OpenAI (`OPENAI_TRANSCRIBE_MODEL`, по умолчанию
`gpt-4o-mini-transcribe`), показывает сотруднику распознанный текст и дальше
обрабатывает его как обычное текстовое сообщение. В мини-аппе расшифровка сначала
приходит карточкой «🎤 Я понял так» с кнопками «✅ Верно», «✏️ Исправить» (текст можно
поправить перед отправкой) и «✖️» (не отправлять). Вопросы AI всегда приходят
текстом. Лимит — 5 минут на голосовое. Переписка общая: отвечать можно и в
мини-аппе, и в обычном чате вперемешку.

## Цели с прогрессом (план/факт по задаче)

Если в поручении есть число по цифрам вечернего отчёта — «Аслбеку 150 звонков за
неделю», «Саидмуроду собрать 30 млн за месяц», «всем по 10 встреч», — AI ставит задачу
как цель (`metric` + `target` в `task_instances`), и бот дальше считает прогресс сам:

- срок цели — до конца последнего дня («недельная» с понедельника — до воскресенья
  включительно); факт — сумма `daily_metrics` за этот отрезок;
- по темпу считается прогноз и сколько нужно в день, чтобы успеть (рабочие дни — как
  у итогов дня);
- прогресс виден сотруднику в карточке задачи в мини-аппе, руководителю — в админке
  (раздел «Цели»), в AI-чате («как Аслбек по цели?») и в сводке 20:00;
- в 12:00 тем, кто по прогнозу не успевает, приходит «осталось N, нужно M в день»
  (не чаще раза в день на цель);
- как только факт дошёл до цели — 🏆 сотруднику и руководителю; если срок вышел, а
  принятая цель не добрана — руководителю итог «N из M (x%)».

Такие задачи AI не закрывает по словам сотрудника («сделал 150 звонков») — только по
цифрам отчётов. Логика — `bot/goals.py`.

## Вечерняя сводка (20:00)

Цифры считает код из `daily_metrics`, AI только комментирует — выдуманных чисел в
сводке нет:

- итоги команды и каждого сотрудника за день, сравнение звонков и назначенных встреч
  с обычным днём этих же людей (среднее по их последним 7 отчётам), кто не сдал итоги;
- выводы AI по текстам стендапов и итогов: лучший день, на что обратить внимание
  (утренний план против вечернего факта, просадки, отставание от плана и целей), что
  сделать завтра;
- цели, зависшие сделки и задачи на сегодня;
- полные тексты отчётов — в админке, раздел «Отчёты сотрудников».

Без `OPENAI_API_KEY` или при ошибке AI сводка приходит без блока выводов.
Логика — `bot/digest.py`.

## Постановка задач текстом (AI)

Руководитель может просто написать боту в личку, например:

> Недельная задача Саидмуроду 150 новых звонков

Бот через OpenAI разберёт фразу (кому, что, какой дедлайн) и сразу отправит
задачу сотруднику — но не с кнопкой «Выполнено», а с кнопкой «🖐 Принять»:
сотрудник подтверждает, что видел и берёт в работу, а фактический результат
(звонки, встречи, деньги) виден из вечерних отчётов, а не из галочки. Руководителю
приходит подтверждение с кнопкой «🚫 Отменить» — на случай, если AI понял задачу
неправильно.

Если сотрудник ещё не привязан к боту (не жал `/start`), задача всё равно
создастся и придёт ему, как только он зарегистрируется. Если к дедлайну задача
не принята — сотруднику и руководителю прилетает уведомление о просрочке.
