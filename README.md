# IROP — Telegram-агент РОПа

Бот-руководитель отдела продаж для троих продажников (Саидмурод, Аслбек,
Муроджон): проводит утренний стендап и вечерний отчёт по вопросам, принимает
разовые задачи от руководителя текстом через AI и следит за дедлайнами.

**Продакшн:** [render.com](https://render.com), сервис `IROP`,
деплой из ветки `master` этого репозитория (`render.yaml` — blueprint).
Публичный адрес мини-аппа = `RENDER_EXTERNAL_URL`, подхватывается автоматически.

## Как это устроено

- `bot/checkins.py` — цели утреннего стендапа и вечернего отчёта (вопросы по ним
  задаёт AI, по одному за раз) и расписание, когда их проводить.
- `bot/templates.py` — фиксированные периодические задачи с одним подтверждением
  (сейчас — недельный отчёт по пятницам).
- `bot/db.py` — SQLite-база (`data/irop.db`): сотрудники, шаблоны, задачи,
  сессии чек-инов.
- `bot/scheduler.py` — фоновые job'ы: запуск стендапа/вечернего отчёта, рассылка
  напоминаний по шаблонам, отметка просрочки, вечерняя сводка руководителю (20:00).
- `bot/handlers.py` — команды, кнопки и разбор текстовых ответов сотрудников.
- `bot/ai.py` — разбор свободного текста руководителя в структурированную задачу
  через OpenAI (function calling).
- `bot/webapp.py` + `bot/webapp_static/index.html` — Telegram Mini App: чат-интерфейс,
  в котором и проходит стендап/итоги дня (см. ниже).
- `bot/telegram_auth.py` — проверка подписи Telegram WebApp initData.

## Деплой на Render (продакшн)

1. Форкните/склонируйте репозиторий, запушьте в свой GitHub.
2. На render.com: **New → Blueprint** → выберите репозиторий — Render прочитает
   `render.yaml` и создаст веб-сервис на плане **Starter** (нужен для работы
   24/7 без «засыпания» и для постоянного диска).
3. Заполните секреты, которые попросит форма (`sync: false` в `render.yaml`):
   `BOT_TOKEN`, `ADMIN_CHAT_ID`, `OPENAI_API_KEY`.
4. После первого деплоя зайдите в сервис → вкладка **Disk** → **Add Disk**:
   имя `irop-data`, mount path `/var/data`, размер 1 GB (~$0.25/мес) — без
   этого SQLite будет стираться при каждом передеплое.
5. `WEBAPP_URL` заполнять не нужно — Render сам даёт `RENDER_EXTERNAL_URL`, бот
   подхватывает его автоматически.

## Локальный запуск (разработка)

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. Узнайте свой `chat_id` (например, напишите боту [@userinfobot](https://t.me/userinfobot)).
3. Скопируйте `.env.example` в `.env` и заполните:

```bash
cp .env.example .env
```

```
BOT_TOKEN=токен_от_BotFather
ADMIN_CHAT_ID=ваш_chat_id
TIMEZONE=Asia/Tashkent
BOT_NAME=Шеф
OPENAI_API_KEY=ключ_от_platform.openai.com
OPENAI_MODEL=gpt-4o-mini
WEBAPP_URL=https://ваш-туннель.loca.lt
WEBAPP_PORT=8080
```

`OPENAI_API_KEY` нужен только для постановки задач текстом (см. ниже). `WEBAPP_URL`
нужен для мини-аппа (см. раздел ниже) — без него бот работает в текстовом режиме
в обычном чате.

4. Установите зависимости (виртуальное окружение `.venv` уже создано и готово):

```bash
.venv/Scripts/python.exe -m pip install -r requirements.txt
```

5. Запустите бота:

```bash
.venv/Scripts/python.exe main.py
```

⚠️ Не запускайте локальную копию одновременно с боевой на Render — оба
процесса дерутся за один и тот же `BOT_TOKEN` через Telegram `getUpdates` и
падают с ошибкой `Conflict`.

## Первый запуск

- Каждый из троих сотрудников пишет боту `/start` и выбирает своё имя кнопкой —
  так его Telegram-аккаунт привязывается к записи в базе.
- Руководитель (chat_id из `.env`) при `/start` получает админ-команды:
  - `/status` — статус задач всех троих за сегодня;
  - `/team` — кто из команды уже подключился.
- Сотруднику доступна команда `/tasks` — список задач на сегодня.

## Мини-апп (Telegram Web App)

Стендап и итоги дня проходят внутри Telegram Mini App — отдельного окна с
чат-интерфейсом, которое открывается по кнопке прямо в Telegram, а не как
разрозненные сообщения в обычном чате. На Render всё уже настроено — этот
раздел актуален только для локальной разработки.

**Как поднять локально для теста** (нужен публичный HTTPS-адрес, `localhost`
Telegram не откроет):

```bash
npx --yes localtunnel --port 8080 --subdomain ваш-уникальный-саб домен
```

Скопируйте выданный `https://....loca.lt` адрес в `WEBAPP_URL` в `.env` и
перезапустите бота. Фиксированный `--subdomain` важен: если туннель
переподключится, адрес останется тем же и не придётся снова лезть в `.env` и
перезапускать бота.

⚠️ При каждом перезапуске самого бота (не туннеля) соединение туннеля с
локальным портом рвётся и его нужно перезапускать заново — это особенность
localtunnel, а не мини-аппа. Для постоянной работы (не только для теста) нужен
нормальный хостинг с собственным доменом вместо туннеля.

Кнопка «💬 Открыть чат» появляется у сотрудника после регистрации (`/start`), а
по утрам/вечерам бот сам присылает кнопку «🚀 Начать рабочий день» /
«🌙 Подвести итоги дня». Открыв мини-апп, сотрудник видит всю переписку за
сегодня и либо жмёт кнопку начала (если чек-ин ещё не начат), либо просто
печатает ответ в поле внизу.

## Утренний стендап и вечерний отчёт

Внутри мини-аппа (или в обычном чате, если `WEBAPP_URL` не настроен) чек-ин ведёт
AI. Фиксированных вопросов нет: у AI есть только цель разговора, а вопросы он
задаёт сам, по одному, исходя из предыдущих ответов — уточняет расплывчатое и не
переспрашивает то, что уже сказано. Как только всё выяснено, AI завершает
разговор (не больше 10 ответов сотрудника).

**Стендап, 09:00** (дедлайн — 30 минут): с какими клиентами вчера говорил, что
они ответили, какие следующие шаги, с кем будет говорить сегодня.

**Итоги дня, 18:30** (дедлайн — 90 минут): звонки (сколько и кому), встречи, КП,
договоры, поступившие деньги — в цифрах, со сверкой с утренним планом.

В контексте у AI — предыдущий отчёт сотрудника и его задачи на сегодня. Сжатый
отчёт с цифрами AI составляет сам и сразу отправляет руководителю. Если сотрудник
не завершил чек-ин к дедлайну — ему приходит напоминание, а руководителю —
уведомление о просрочке. Цели чек-инов редактируются в `GOALS` в
`bot/checkins.py`.

## Постановка задач текстом (AI)

Руководитель может просто написать боту в личку, например:

> Недельная задача Саидмуроду 150 новых звонков

Бот через OpenAI разберёт фразу (кому, что, какой дедлайн) и сразу отправит
задачу сотруднику — но не с кнопкой «Выполнено», а с кнопкой «🖐 Принять»:
сотрудник подтверждает, что видел и берёт в работу, а фактический результат
(звонки, встречи, деньги) виден из вечерних отчётов, а не из галочки. Руководителю
приходит подтверждение с кнопкой «🚫 Отменить» — на случай, если AI понял задачу
неправильно.

Если сотрудник ещё не привязан к боту (не жал `/start`), задача всё равно
создастся и придёт ему, как только он зарегистрируется. Если к дедлайну задача
не принята — сотруднику и руководителю прилетает уведомление о просрочке.

## Дальше — прокачка

Это MVP-каркас. Дальше можно наращивать:
- постоянный HTTPS-хостинг для мини-аппа вместо туннеля;
- парсинг чисел из вечерних ответов в таблицу KPI (сейчас это просто текст);
- персонализированные разовые задачи по конкретному сотруднику;
- интеграцию с CRM/таблицей вместо самоотчёта;
- более живой тон сообщений, эскалации и т.д.
