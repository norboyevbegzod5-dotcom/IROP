# Интеграция IROP ↔ GFSupport: факты дня вместо самоотчёта

> Документ для ИИ-разработчика проекта IROP. Содержит всё, что нужно, чтобы
> развернуть интеграцию: адрес, формат, готовый код и точные места правок.
> Сторона GFSupport уже готова и работает в проде.

## 1. Зачем это

Сейчас источник правды о продажах в IROP — **самоотчёт менеджера**: вечером он
сам называет звонки, КП, договоры и деньги. GFSupport (CRM отдела) те же
события знает объективно: звонки приходят с АТС, КП создаются в системе,
оплаты отмечаются в сделке.

Задача интеграции — не заменить стендап, а **снять с человека диктовку цифр**:

- цифры «Шеф» берёт из CRM сам;
- у человека спрашивает то, чего система знать не может: что ответил клиент,
  почему тянет, о чём договорились, что мешает;
- при расхождении («ты сказал 30 звонков, в системе 16») — спрашивает об этом
  прямо, а не записывает молча.

Конечная цель: форма итогов дня с девятью полями отмирает, стендап остаётся
разговором про клиентов.

## 2. Что отдаёт GFSupport

### Адрес

```
GET https://www.gfsupport.uz/api/support/public/agent-facts?key=КЛЮЧ
```

Адрес с `www`: без него домен отвечает перенаправлением 308. `aiohttp` следует
за ним сам, но лучше сразу указывать конечный — меньше лишнего запроса.

| Параметр | Что делает |
|---|---|
| `key` | ключ доступа, обязателен |
| `date` | день для блока `items` (по умолчанию сегодня) |
| `from`, `to` | период для блока `people` (по умолчанию = `date`, потолок 92 дня) |
| `who` | ваш `employees.key` — вернуть только этого человека |

Часовой пояс — **Asia/Tashkent**, как у вас. Только GET, только чтение.
Коды: `200`, `401` (нет или неверный ключ), `400` (кривая дата или период > 92 дней).

### Как поля ложатся на ваши `db.METRIC_FIELDS`

| Ваше поле | Поле CRM | Что считается |
|---|---|---|
| `calls` | `calls` | все звонки за день; есть разбивка `calls_answered` / `calls_missed` |
| `meetings_held` | `meetings_held` | встречи, отмеченные проведёнными |
| `meetings_new` | `meetings_new` | встречи, назначенные в этот день |
| `kp_count` | `kp_count` | отправленные КП |
| `kp_sum` | `kp_sum` | сумма по сделкам этих КП (подписка + разовое), сумы |
| `contracts_count` | `contracts_count` | сделки, выигранные в этот день |
| `contracts_sum` | `contracts_sum` | их сумма, сумы |
| `payments_sum` | `payments_sum` | деньги, поступившие в этот день |
| `new_connections` | **нет** | CRM такого не считает — оставить самоотчёту |

### Что из этого для чего

| Задача AI-РОПа | Что брать |
|---|---|
| Итоги дня: не спрашивать цифры | `items` за `date` |
| Сверить слова с системой | `items` + вопрос о разнице |
| Сводка руководителю 20:00 | `people[].total` + `people[].days` за неделю |
| «Что у тебя зависло» | `people[].pipeline.stalled`, `deals[]` где `stalled: true` |
| «У кого нет следующего шага» | `pipeline.no_next_step`, `deals[]` где `next_step` пуст |
| «С кем ты сегодня говорил» | `called_today` |
| «Почему падают сделки» | `closed.lost_reasons` |
| Прогресс цели «150 звонков» | сумма `days[].calls` за срок |
| Разговор про конкретного клиента | `deals[]` — этап, сколько стоит, чем занят |

## 3. Границы — что неверно считать фактом

1. **`new_connections` CRM не отдаёт.** Поле остаётся вопросом к человеку.
2. **Звонок привязан к обращению, а не к сотруднику.** АТС не сообщает, кто
   звонил, поэтому CRM считает звонок по ответственному за обращение, а если
   его нет — по владельцу сделки. На 02.10.2026 так определяются 140 звонков
   из 160. Остальные не попадают ни к кому: это честнее, чем делить поровну.
   **Вывод для AI:** факт CRM — это «не меньше, чем», а не «ровно столько».
   Если менеджер называет больше — это не обязательно ложь; спросить, откуда
   разница (личный телефон, звонок без карточки).
3. **Расхождение — повод для вопроса, а не обвинение.** Формулировка «в системе
   16, ты говоришь 30 — где остальные?» допустима; «ты соврал» — нет.
4. **CRM не знает содержания разговора.** Что сказал клиент, какие возражения,
   о чём договорились — только от человека.
5. **`pipeline` — состояние на сейчас, а не за период.** Открытые сделки,
   зависшие, задачи считаются на момент запроса; `days`, `total` и `closed` —
   за период `from`–`to`.
6. **Суммы считаются по-разному.** `kp_sum` и `contracts_sum` — подписка плюс
   разовое по сделке; `pipeline.amount_monthly` — только подписка по открытым.
   Всё в сумах, целыми.
7. **Персональных данных нет.** Телефоны, имена контактов и переписка наружу
   не отдаются. Названия заведений есть — это предмет работы, а не личные
   данные.
8. **Люди без сопоставления приходят с `who: null`.** Такие записи игнорировать:
   это сотрудники GFSupport, которых нет в IROP.

## 4. Готовый модуль для IROP

Создать файл `bot/crm.py`. Зависимостей ставить не нужно: `aiohttp` уже в
`requirements.txt`.

```python
# Данные из GFSupport: объективные цифры и состояние воронки по менеджерам.
#
# CRM знает звонки, КП, выигранные сделки и оплаты точнее самоотчёта, поэтому
# «Шеф» берёт их оттуда, а у человека спрашивает то, чего система знать не
# может. Если CRM недоступна, бот работает как раньше: интеграция усиливает
# разговор, но не является его условием.

import asyncio
import logging
from datetime import date, datetime, timedelta

import aiohttp

from bot.config import CRM_FACTS_URL, CRM_FACTS_KEY

log = logging.getLogger(__name__)

_TIMEOUT = aiohttp.ClientTimeout(total=10)
_CACHE_TTL_SEC = 300
_cache: dict[tuple, tuple[float, dict]] = {}


async def _get(params: dict) -> dict:
    """Запрос к CRM. Пустой словарь = «система не ответила», это не нули."""
    if not CRM_FACTS_URL or not CRM_FACTS_KEY:
        return {}
    cache_key = tuple(sorted(params.items()))
    now = datetime.now().timestamp()
    hit = _cache.get(cache_key)
    if hit and now - hit[0] < _CACHE_TTL_SEC:
        return hit[1]
    try:
        async with aiohttp.ClientSession(timeout=_TIMEOUT) as session:
            async with session.get(CRM_FACTS_URL, params={**params, "key": CRM_FACTS_KEY}) as resp:
                if resp.status != 200:
                    log.warning("CRM: статус %s", resp.status)
                    return {}
                data = await resp.json()
    except (aiohttp.ClientError, asyncio.TimeoutError) as exc:
        log.warning("CRM недоступна: %s", exc)
        return {}
    _cache[cache_key] = (now, data)
    return data


async def facts_for_day(day: str | None = None) -> dict[str, dict]:
    """Цифры за день: {employees.key: {calls, kp_count, ...}}."""
    day = day or date.today().isoformat()
    data = await _get({"date": day})
    return {i["who"]: i for i in (data.get("items") or []) if i.get("who")}


async def snapshot(days: int = 7) -> dict[str, dict]:
    """Полный снимок за последние N дней: {employees.key: {...}}.

    Внутри: days (по дням), total, pipeline, tasks, closed, deals, called_today.
    """
    today = date.today()
    data = await _get({
        "from": (today - timedelta(days=days - 1)).isoformat(),
        "to": today.isoformat(),
        "date": today.isoformat(),
    })
    return {p["who"]: p for p in (data.get("people") or []) if p.get("who")}


def line(fact: dict | None) -> str:
    """Строка цифр для промпта. Без факта — честное «система молчит»."""
    if not fact:
        return "по системе: данных нет"
    return (
        f"по системе: звонки {fact['calls']} "
        f"(разговор {fact['calls_answered']}, недозвон {fact['calls_missed']}); "
        f"встреч проведено {fact['meetings_held']}, назначено {fact['meetings_new']}; "
        f"КП {fact['kp_count']} на {fact['kp_sum']:,} сум; "
        f"договоры {fact['contracts_count']} на {fact['contracts_sum']:,} сум; "
        f"поступило {fact['payments_sum']:,} сум"
    ).replace(",", " ")


def pipeline_line(snap: dict | None) -> str:
    """Состояние воронки: о чём спрашивать на стендапе."""
    if not snap:
        return ""
    p = snap.get("pipeline") or {}
    t = snap.get("tasks") or {}
    parts = [
        f"открытых сделок {p.get('open', 0)}",
        f"зависло {p.get('stalled', 0)}" if p.get("stalled") else "",
        f"без следующего шага {p.get('no_next_step', 0)}" if p.get("no_next_step") else "",
        f"задач просрочено {t.get('overdue', 0)}" if t.get("overdue") else "",
    ]
    return "по системе: " + ", ".join(x for x in parts if x)


def stuck_deals(snap: dict | None, limit: int = 5) -> list[dict]:
    """Зависшие сделки — о них и стоит спрашивать поимённо."""
    deals = (snap or {}).get("deals") or []
    stuck = [d for d in deals if d.get("stalled") or not d.get("next_step")]
    stuck.sort(key=lambda d: d.get("days_on_stage", 0), reverse=True)
    return stuck[:limit]


def deals_line(snap: dict | None, limit: int = 5) -> str:
    """Короткий список зависшего для промпта."""
    rows = stuck_deals(snap, limit)
    if not rows:
        return ""
    items = [
        f"{d.get('brand') or 'без названия'} — {d.get('stage')}, {d.get('days_on_stage')} дн."
        for d in rows
    ]
    return "давно без движения: " + "; ".join(items)


def called_line(snap: dict | None) -> str:
    """С кем говорили сегодня — чтобы спрашивать про конкретных клиентов."""
    rows = (snap or {}).get("called_today") or []
    if not rows:
        return ""
    talked = [r["name"] for r in rows if r.get("outcome") == "разговор"]
    missed = [r["name"] for r in rows if r.get("outcome") != "разговор"]
    out = []
    if talked:
        out.append("поговорил: " + ", ".join(talked[:8]))
    if missed:
        out.append("не дозвонился: " + ", ".join(missed[:8]))
    return "; ".join(out)
```

## 5. Сопоставление людей

Соответствие `employees.key` → идентификатор сотрудника в CRM хранится **на
стороне GFSupport** (настройка `irop_api`), владелец задаёт его один раз для
троих: `saidmurod`, `aslbek`, `murodjon`. От вас ничего не требуется — поле
`who` в ответе уже содержит ваш ключ. Если `who` пришёл `null`, человек не
сопоставлен: такие записи игнорировать.

## 6. Что изменить в IROP

### 6.1 Итоги дня (`bot/checkins.py`) — главное

**Сейчас:** AI спрашивает цифры, человек диктует, `_clean_metrics` сохраняет.

**Нужно:** цифры берутся из CRM, у человека спрашивается то, чего в них нет.

1. В `_context(...)` добавить `"crm": crm.line(fact)` для этого сотрудника
   за `session["session_date"]` (через `await crm.facts_for_day(...)`).
2. В промпт вечернего чек-ина (`bot/ai.py`, инструкция `checkin_step`) добавить:

   > Цифры по звонкам, встречам, КП, договорам и деньгам у тебя уже есть
   > из системы — они в блоке «по системе». Не проси их диктовать.
   > Спроси: что было с клиентами, какие договорённости, что мешает,
   > и сколько новых подключений (этого в системе нет).
   > Если менеджер называет цифру, которая расходится с системой больше чем
   > на четверть, спроси, откуда разница — спокойно, без обвинений: звонок
   > с личного телефона или без карточки в системе не виден.
   > Если в блоке написано «данных нет» — веди разговор как раньше.

3. В `submit_form(...)` заполнять поля из CRM значениями по умолчанию, человеку
   оставить `new_connections` и комментарий. Если CRM молчит — как сейчас.

### 6.2 Стендап (`bot/checkins.py`, 09:00) — теперь предметный

Утром цифры не нужны, но полезно знать, **о чём спрашивать**. Подставить
в контекст стендапа:

- `crm.pipeline_line(snap)` — «открытых 27, зависло 17, без следующего шага 4,
  задач просрочено 26»;
- `crm.deals_line(snap)` — поимённо, что давно не движется;
- `crm.called_line(snap)` — с кем говорил вчера.

Правило в промпт:

> В блоке «по системе» — состояние сделок и с кем человек говорил.
> Спрашивай про конкретные заведения из этого списка, а не «как дела вообще».
> Если сделка висит на этапе больше двух недель — спроси, что с ней и нужно ли
> её закрывать.

### 6.3 Сводка руководителю (`bot/admin_context.py`)

Рядом с `_metrics_line(m)` добавить `crm.line(...)` за тот же день и
`crm.pipeline_line(...)`. AI руководителя увидит оба числа и состояние воронки.

### 6.4 Цели (`bot/goals.py`)

Факт по метрике `calls` считать из CRM: сумма `days[].calls` за срок цели.
Тогда «150 звонков за неделю» опирается на систему, а не на память. Делать
вторым шагом, после сверки в итогах дня.

### 6.5 Мини-CRM (`bot/deals.py`) — чего НЕ делать

Не переносить сделки из CRM в вашу таблицу `deals`: тогда появятся два списка,
которые разойдутся. Правильнее показывать сделки CRM как есть (`people[].deals`)
и постепенно отказаться от своей мини-CRM — она нужна была, пока не было
доступа к настоящей.

## 7. Порядок внедрения

1. Завести на Render переменные из `CRM_FACTS_KEY.txt` (ключ уже выпущен,
   сопоставление троих задано — запрашивать ничего не нужно).
2. Добавить `bot/crm.py` и переменные в `bot/config.py`.
3. Проверить вручную: `GET …?date=вчера` — должны прийти трое с ненулевыми
   числами (проверено: 01.10.2026 — Муроджон 50 звонков, Саидмурод 19,
   Аслбек 6 и 2 КП).
4. Подключить `crm.line()` в `admin_context.py` — безопасно, меняется только
   текст для AI руководителя.
5. Подключить в итоги дня: сначала показом факта, потом убрать вопросы о цифрах.
6. Подключить в стендап `pipeline_line` и `deals_line` — разговор станет про
   конкретные заведения.
7. Через неделю посмотреть, где самоотчёт расходился с системой, и решать,
   оставлять ли форму итогов дня вовсе.

## 8. Безопасность

- Ключ — в переменной окружения, не в коде и не в логах; в сообщениях бота
  не показывать.
- Доступ только на чтение; изменить что-либо в CRM через этот адрес нельзя.
- Ключ перевыпускается на стороне GFSupport, старый сразу перестаёт работать.
- Данные — цифры по сотрудникам своей компании; персональных данных клиентов
  в ответе нет.

## 9. Если понадобится больше

Адрес отдаёт всё состояние менеджера: цифры по дням, воронку, задачи,
закрытое с причинами, открытые сделки и с кем говорили. Этого хватает
на стендап, итоги дня, сводку руководителю и разговор про конкретную сделку —
за новыми полями возвращаться не нужно.

Чего в нём нет и не будет без отдельного решения: содержание переписки
с клиентом, записи и расшифровки звонков, контакты. Если понадобится что-то
из этого или запись в CRM (поставить задачу, двинуть этап из бота), — это уже
не один адрес, а набор инструментов для AI (MCP) с отдельными правами.
